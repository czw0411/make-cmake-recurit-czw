# Task 4：思考题

## 1. Make 和简单的 build.sh 有什么区别？

build.sh是一个按顺序执行的全量脚本，即每次运行都会把项目里所有的gcc命令从头执行一遍，不管文件是否被修改过，也不管文件之间的依赖关系。而Make则是基于依赖关系的增量构建工具，通过比较文件时间戳来判断哪些目标过期，只有被修改的文件及其下游目标才会被重新编译，其余直接复用已有的.o文件。

## 2. CMake 是编译器吗？

执行 `cmake --build build` 时，最终是谁在编译 C 源文件？

不是。CMake本身不做任何编译工作，它是构建系统的生成器。CMake读取CMakeLists.txt，分析项目的源文件、依赖库和编译选项后，生成一份构建描述文件，真正把C源码翻译成机器码的是编译器gcc。

## 3. 为什么不希望每次都重新编译所有 `.c` 文件？

因为编译是整个构建过程中成本最高的一步，每个.c文件都要经过预处理、词法语法分析、优化和代码生成，全量编译这些文件可能需要花费更多时间；而在日常开发中，每次修改往往只涉及一两个文件。并且没被修改的源文件，其上次编译产生的目标文件（.o）依然有效，可以直接复用，所以重复执行没有必要。
